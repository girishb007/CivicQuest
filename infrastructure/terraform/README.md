# AWS deployment configuration

Terraform 1.9.8 / AWS provider 5.100.0 initialization and validation passed locally. This is not a deployed or launch-approved environment.

Inputs include an existing VPC with private subnets in two availability zones, public ALB subnets, private outbound NAT or AWS endpoints, image digests, regional ALB TLS certificate, domain, and application secret ARN. Application secrets must contain the database DSN (including `sslmode=require`), application secret, and Google credentials. Database credentials are generated by RDS Secrets Manager; populate the application DSN after provisioning. Do not put secret values into tfvars or source control.

Services start with zero desired tasks. After approved provisioning, run the migration task, import the approved geography/ownership data, review the public-data gate, and then scale API/worker/web to their reviewed counts. Synthetic seeding is not part of production deployment.

The configuration includes ECS, RDS, Redis, private S3 buckets, SQS, IAM, CloudWatch logs, ALB TLS, and an alert subscription. CloudFront forwards authenticated traffic with caching disabled. Live IAM/CDN behavior remains unvalidated. Configure the origin DNS name to point to the ALB and ensure both viewer/origin hostnames are covered by the ALB certificate; the CloudFront certificate must be in us-east-1. Backend media access remains authorized on every request. No S3 bucket is public.

EventBridge Scheduler definitions run retention daily and the India Post/BMC/Digital Sansad reference refresh on the first day of each month at 03:00 Asia/Kolkata. They default to disabled through `enable_schedules = false`. Enable them only after the private subnets have outbound access to the official HTTPS sources and an operator has reviewed the first manual refresh. A malformed or incomplete upstream snapshot rolls back the complete reference refresh transaction, preserving the last reviewed data.

Use encrypted remote Terraform state with restricted access before provisioning. Run `terraform init -backend=false` and `terraform validate` for local validation. Infrastructure creation and domain changes require the separately approved live rollout.
